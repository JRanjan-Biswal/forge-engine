# Expo (React Native) — conventions & review lens

## Conventions
- **Navigation is files:** screens live in `src/app/` (expo-router; `app/` in older projects). One `_layout.tsx` per stack/tab group; typed routes with `Href`; deep links come from the file tree, so name routes the way URLs should read.
- **Install native packages with `npx expo install <pkg>`** so versions match the SDK; never hand-pick versions of react-native libraries.
- **Every screen state:** loading (skeleton or `ActivityIndicator` with an accessible label), error with retry, empty with a next action, success. Respect safe areas (`react-native-safe-area-context`) and the keyboard (`KeyboardAvoidingView` / keyboard-aware scroll) on forms.
- **Styling:** forge tokens from `design/dist/theme.ts`; `StyleSheet.create` or the project's styling library; no literal colours. Support dark mode with `useColorScheme` and the token themes.
- **Motion:** `react-native-reanimated` for animation on the UI thread; honour reduced motion (`useReducedMotion`) per the motion spec.
- **Data:** a typed API client generated from `contracts/openapi.yaml` (or the Supabase client); server state in a query cache (e.g. TanStack Query) with retries off for mutations; never block the JS thread with large sync work.
- **Secrets:** the app bundle is public. Only `EXPO_PUBLIC_*` env vars reach the app and they are visible to anyone — no service keys, ever. Tokens in `expo-secure-store`, not AsyncStorage.
- **Platforms:** check iOS and Android differences (back button, permissions prompts, notches); request permissions just-in-time with a reason string in `app.json`.
- **Accessibility:** `accessibilityRole`, `accessibilityLabel`, ≥ 44×44 pt touch targets, Dynamic Type (`allowFontScaling`) not disabled.
- **Builds:** EAS (`eas build`) profiles in `eas.json`; config in `app.config.ts`; bump `version`/build numbers via EAS, not by hand.

## Review lens
- [ ] Native dependencies installed with `expo install` (versions match the SDK); no incompatible library added.
- [ ] No secret in `EXPO_PUBLIC_*`, `app.json` `extra`, or source; auth tokens stored with `expo-secure-store`.
- [ ] Each screen handles loading / error / empty / success, safe areas and the keyboard.
- [ ] Lists use `FlatList`/`FlashList` with stable keys — no `.map` over unbounded data in a ScrollView.
- [ ] Animations run on the UI thread (Reanimated) and respect reduced motion.
- [ ] Permissions requested just-in-time with usage descriptions; denial path handled.
- [ ] Accessibility labels/roles on interactive elements; touch targets ≥ 44 pt.
- [ ] Tokens only — no literal colours or font sizes.
- [ ] Works on both iOS and Android (Maestro flow or noted manual check per platform).

## Pitfalls
- `jest --watchAll` (the old template's test script) never exits in CI — run jest with `--ci --watchAll=false`.
- `expo-env.d.ts` is gitignored and generated by the Expo CLI; a bare `tsc` in CI fails on CSS-module and global CSS imports until it exists.
- `expo lint` without an ESLint config installs packages; set it up once, commit `eslint.config.js`.
- Expo Go cannot load custom native code; use a development build (`npx expo run:ios|android` or EAS) once you add native modules.
- `Date`/`Intl` and `fetch` behave differently on Hermes vs web — test on device.
